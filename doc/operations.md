# Запуск и эксплуатация

## Необходимые компоненты

- Python; локальное окружение проекта было создано для CPython 3.10.
- Зависимости из корневого `requirements.txt`.
- Доступ к существующей MySQL-базе с объектами из [описания данных](data.md), а для регистрации — к `fsbr_aux.new_players`.
- Отдельная база пользователей SQLAlchemy; по умолчанию SQLite.
- Учётные данные OAuth, если требуется вход.

Установка зависимостей не создаёт основную БД. Дамп, DDL и миграции MySQL в составе исходников приложения отсутствуют. Команды ниже — инструкция для настроенного окружения, а не отчёт об успешно выполненном запуске.

## Подготовка в PowerShell

Из корня проекта:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
$env:PYTHONPATH = "$PWD;$PWD\src"
```

Оба пути нужны текущей схеме импортов: приложение импортирует `src.*`, а конфигурацию — как `defaults` и `settings`. Запускайте из корня также потому, что проверка фотографий использует относительный путь `src/static/foto`.

## Локальная конфигурация

Создайте или настройте `src/settings.py`. Этот файл исключён из Git; не публикуйте реальные значения секретов. Пример структуры:

```python
import os

SECRET_KEY = os.environ['FSBR_SECRET_KEY']
DEBUG = False
DB_HOST = os.environ['FSBR_DB_HOST']
DB_USER = os.environ['FSBR_DB_USER']
DB_PASSWORD = os.environ['FSBR_DB_PASSWORD']
DB_DB = os.environ['FSBR_DB_NAME']
SQLALCHEMY_DATABASE_URI = 'sqlite:///users.sqlite'
OAUTH_CREDENTIALS = {
    'google': {'id': os.environ['GOOGLE_CLIENT_ID'], 'secret': os.environ['GOOGLE_CLIENT_SECRET']},
    'facebook': {'id': os.environ['FACEBOOK_CLIENT_ID'], 'secret': os.environ['FACEBOOK_CLIENT_SECRET']},
    'twitter': {'id': os.environ['TWITTER_CLIENT_ID'], 'secret': os.environ['TWITTER_CLIENT_SECRET']},
}
```

Это пример чтения переменных через файл настроек: само приложение не загружает переменные `FSBR_*` автоматически. При таком примере переменные нужно задать до импорта приложения. `OAuthSignIn.get_provider` при первом обращении создаёт сразу все три адаптера, поэтому конфигурация должна содержать все три ключа, даже если интерфейс показывает только Google и Facebook. Наличие ключей само по себе не обеспечивает доступность входа у провайдера.

| Параметр | Использование / значение по умолчанию |
| --- | --- |
| `SECRET_KEY` | Подпись сессии и работа CSRF; задаётся локально |
| `DB_HOST`, `DB_USER`, `DB_PASSWORD`, `DB_DB` | Соединение PyMySQL; обязательны для запросов основной БД |
| `SQLALCHEMY_DATABASE_URI` | База пользователей; `sqlite:///users.sqlite` |
| `SQLALCHEMY_TRACK_MODIFICATIONS` | `False` |
| `DEBUG` | В `defaults.py` установлено `True`; для эксплуатации переопределить |
| `OAUTH_CREDENTIALS` | Словарь провайдеров с `id` и `secret` |
| `CSRF_ENABLED` | В `defaults.py` установлено `True`; отдельно проверить настройки Flask-WTF используемой версии |
| `MINIFY_HTML` | `True`, однако подключение HTMLMIN закомментировано |

Относительный URI SQLite не гарантирует использование имеющегося `src/users.sqlite`. Перед инициализацией проверьте `app.instance_path` и фактический `db.engine.url` в контексте приложения; при необходимости задайте абсолютный URI нужного файла.

## Инициализация и запуск

Только для выбранной базы пользователей, после проверки её адреса:

```powershell
.\.venv\Scripts\python.exe -m flask --app src.start:app initdatabase
.\.venv\Scripts\python.exe -m flask --app src.start:app run --host 127.0.0.1 --port 5000
```

`initdatabase` вызывает `db.create_all()`: создаёт отсутствующие таблицы пользователей, ролей, связей и флагов. Команда не создаёт MySQL-схему, не переносит существующие таблицы и не назначает роли. Назначение `Admin`, `AddPlayers` и привязка `User.fsbr` требуют отдельного администрирования; интерфейса управления пользователями в проекте нет.

Проверка без записи данных: открыть `/`, затем `/players/`; при доступной MySQL проверить `/tourns/xml/`, `/rate/xml/` и карточку известного игрока. Проверить XML-парсинг и соответствие данных ожидаемой базе, затем экспорт `/misc/ListXL/`. Проверки входа и добавления проводить в тестовом окружении.

## Развёртывание и обслуживание

WSGI-точка входа — `src.start:app`, с доступными корнем проекта и `src` в пути импорта. Готового production-конфига сервера или reverse proxy в исходниках нет. В зависимостях присутствует Gunicorn, но его наличие не является готовой конфигурацией развёртывания для Windows. Политику доверия к прокси нужно согласовать с существующим `ProxyFix`.

Резервировать нужно основную MySQL-базу, `fsbr_aux`, фактически используемую базу пользователей и отдельно фотографии `src/static/foto`, если они есть. Секреты хранить отдельно от репозитория. Механизма автоматического резервирования в приложении нет.

Флаг `locked` ограничивает добавление игроков через обработчик, но не блокирует чтение MySQL и не является блокировкой на уровне СУБД. Администратор переключает его через `/toggle_lock_state`.

## Типовые проблемы

| Симптом | Что проверить |
| --- | --- |
| Не найден `src`, `defaults` или `settings` | Рабочий каталог и оба пути в `PYTHONPATH` |
| Ошибка подключения MySQL | Четыре параметра `DB_*`, сеть, права и наличие схемы |
| `no such table: users` / `flags` | Фактический файл SQLite и выполнение `initdatabase` для него |
| Ошибка рейтинга при пустой истории | `Helper.getDate` требует непустого списка дат |
| Добавление сообщает общую ошибку | Права на `fsbr_aux`, поля формы, `User.fsbr`; исключения сервисом скрываются |
| Вход Twitter завершается ошибкой | Несовпадение `username` и `nickname` в текущем коде |
| Не отображаются фотографии | Каталог запуска и наличие файлов `src/static/foto/<id>.jpg` |
