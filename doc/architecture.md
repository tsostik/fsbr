# Архитектура

## Поток запроса

```text
Браузер / внешний потребитель
        ↓
src/start.py — маршруты Flask, вход, HTTP-ответы
        ↓
players.py / tournaments.py / rate.py / service.py
        ↓
db.BaseIFace + queries.Queries → MySQL
        ↓
interface.py / misc.py / RateTours.py → XML / JSON / XLS

Вход и права: start.py → oauth.py → внешний OAuth
                     → users.py → SQLAlchemy → база пользователей
HTML: start.py → templates/*.htm + static/*
```

Приложение создаётся при импорте `src.start`, фабрики приложения и Blueprint нет. Настройки загружаются последовательно из модулей `defaults` и `settings`; второй переопределяет первый. Flask-Login, Flask-SQLAlchemy и Flask-Excel подключаются к общему объекту `app`. WSGI-приложение обёрнуто в `ProxyFix`.

## Основные сценарии

**Карточка игрока.** `getPlayerXml` открывает `BaseIFace`, загружает игрока, результаты, административные и судейские позиции, прочие события, внешние ID, лучшие рейтинговые показатели и клубные баллы. После закрытия соединения возвращает XML объекта `Player`.

**Турнир.** Загружается заголовок, вложенные турниры и цепочка предков. По типу турнира выбирается отдельный SQL-загрузчик индивидуальных, парных, командных или сессионных участников. Сериализация находится в `Tournament` и классах `TournamentRecord*`.

**Рейтинг.** Приложение выбирает доступную дату истории и читает готовые значения из MySQL. Прогноз также загружается из объекта БД `rate_forecast`. Полного процесса расчёта и обновления рейтингов в этом приложении нет.

**Новый игрок.** Обработчик требует входа, проверяет флаг блокировки и Flask-WTF-форму. Сервис создаёт `Player`, передаёт `current_user.fsbr` как автора и записывает заявку в `fsbr_aux.new_players`. Это не вставка в основную таблицу `players`; дальнейший перенос заявки в основной реестр в проекте не реализован.

## Связность

Бизнес-объекты сами формируют XML, слой доступа к данным одновременно преобразует записи БД в эти объекты. Использование `import *` в нескольких модулях создаёт неявные зависимости, например доступ к `Helper`, `datetime` и `et`. Для сопровождения полезно учитывать, что `RateRecord` в `interface.py` и одноимённый класс в `RateTours.py` имеют разное назначение.
