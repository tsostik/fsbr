# Результаты анализа

Наблюдения основаны на статическом чтении исходников. Это список для сопровождения; исправления приложения в рамках подготовки документации не вносились.

## Приоритетные проверки

| Наблюдение | Последствие | Предлагаемое действие |
| --- | --- | --- |
| `add_player` проверяет вход, но не роль `AddPlayers`; роль проверяется только шаблоном | Прямой POST может обойти ограничение интерфейса | Проверять право на сервере до записи |
| Переключение `locked` выполняется GET-запросом | Состояние изменяется через ссылку без проверки формы | Перенести изменение на POST с CSRF |
| `next` используется для перенаправлений без локальной проверки адреса | Возможен переход на внешний адрес | Ограничить разрешённые адреса возврата |
| OAuth2-адаптеры явно не создают и не проверяют `state` | Нужно подтвердить защиту потока входа | Проверить поведение `rauth` и добавить явную проверку при необходимости |
| `DEBUG = True` в значениях по умолчанию | Режим отладки может попасть в развёртывание | Явно задавать `False` вне разработки |
| XML и XLS доступны без входа; XLS содержит email | Доступ к персональным данным определяется текущими публичными маршрутами | Согласовать состав выгрузки и права с владельцем данных |

## Надёжность и совместимость

- **Twitter:** callback возвращает `username`, а `find_or_add_user` ожидает `nickname`. Для нового Twitter-пользователя этот путь может завершиться `KeyError`.
- **OAuth-конфигурация:** первый запрос одного провайдера создаёт все адаптеры. Отсутствующая конфигурация другого провайдера может сломать выбранный вход.
- **Ошибка добавления:** `players.addPlayer` перехватывает любое исключение и возвращает `-1` без журналирования. Причина ошибки теряется для оператора.
- **Конкурентное добавление:** проверка свободного ID и вставка разделены; требуется проверка ограничений БД и атомарности распределения номера.
- **Пустая история:** `Helper.getDate` обращается к первому элементу без проверки. API рейтинга зависит от наличия истории.
- **Пустой клуб:** `getClubList` обращается к `clubs[0]`; неизвестный клуб может вызвать исключение.
- **Список «Сириус»:** `getStudents` всегда возвращает название «Спутник», включая ветку `sirius`. Заголовок HTML может не соответствовать выборке.
- **Пути и настройки:** смешаны импорты `src.*` и конфигурации без `src`; фотографии ищутся относительно текущего каталога. Запуск зависит от рабочего каталога и `PYTHONPATH`.
- **SQLite:** наличие `src/users.sqlite` не доказывает, что относительный URI SQLAlchemy указывает именно на этот файл.
- **Зависимости:** `requirements.txt` сочетает Flask 3.1 / SQLAlchemy 2 с более старыми расширениями и вспомогательными библиотеками. Нужна проверка установки и основных сценариев в чистом окружении. Flask-Script указан, но CLI в `start.py` использует Flask CLI; HTMLMIN закомментирован. Версии здесь описаны по файлу проекта, их актуальность и уязвимости не проверялись.

## Сопровождение

Нет общей схемы ошибок API, миграций MySQL, сценария начального назначения ролей и воспроизводимого production-конфига. SQL сочетает параметризацию и строковое форматирование; каждый новый пользовательский параметр нужно проверять по фактическому пути до запроса. В поиске имя экранируется, поэтому само наличие `.format` не доказывает SQL-инъекцию во всех запросах.

Рекомендуемая последовательность дальнейшей работы:

1. Воспроизвести установку, подтвердить пути обеих БД и проверить чтение данных на тестовой копии.
2. Исправить серверную проверку прав, изменение флага через GET и обработку адресов возврата; проверить OAuth.
3. Добавить журналирование ошибок добавления и обработку пустых данных.
4. Закрепить распределение ID ограничениями и транзакционной схемой на стороне БД.
5. Подготовить миграции, управляемую конфигурацию и проверки ключевых сценариев: даты рейтинга, права, регистрация и сериализация.
6. После стабилизации выделять маршруты в Blueprint и заменять неявные импорты явными.

При обновлении кода сначала сверяйте [HTTP-интерфейс](api.md), [данные](data.md) и [инструкцию запуска](operations.md): это наиболее чувствительные к изменениям части документации.
